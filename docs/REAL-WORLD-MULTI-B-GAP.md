# Real-world multi-b gap map — what we must add

**Purpose:** Study of AI + SMB / trades platforms → honest map of what Orvius
**has**, what is **missing for multi-b**, and what we **add next** (code vs founder).

**Evidence:** `docs/CATEGORY-WIN-REQUIREMENTS.md`, `docs/AI-CATEGORY-STUDY.md`,
`docs/MULTI-B-STRICT.md`, live `life:check` / `founder:next`, product inventory 2026-09-23.

**Rule:** Multi-b is not “more screens.” It is **density + money + undefeated
wedge + trust**. Feature theater that skips call→cash fails.

emergency tickets $300–$850+, no-shows, cold estimates, cash before materials,
dispatch chaos, Angi-style lead rot, reviews, license/insurance admin.

## Decision

**Study complete.** Multi-b checklist is not “build ServiceTitan.” It is:

1. Undefeated **call → paid job** on live shops  
2. **Money rail** live (SaaS + Connect)  
3. **Metro density** (10+ proving partners)  
4. Then integrations / OS depth **when pulled**

**Next action:** execute **Tranche 1** in code unless founder overrides to
Resend / outreach / Connect live first (those are the actual multi-b reds).
